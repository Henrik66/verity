Verity programs run on CPython and use Python libraries directly. This section specifies the conversions at the boundary between Verity truths and Python values.

Calling Python from Verity

Any module importable by the executing Python interpreter can be imported. Python functions, classes and values are used with ordinary call, attribute and subscription syntax. [[settled]]

import json
from statistics import mean

scores = json.loads("[61, 74, 88]")
print(mean(scores))

74.33333333333333

Rule 1: lifting Python booleans

A Python bool that appears where a truth is required is lifted into a truth with the same value. The positions that require a truth are: the operands of not, and and or, the left operand of because, the body of a quantifier, and the argument of testimony.explain. [[settled]]

The lifted truth's testimony is a lifted node: [[proposed]]

  • When the bool is the direct result of a call, the node renders the callee and argument values: str.isdigit('4a') returned False.
  • Otherwise it renders the source text: flag returned True.
from testimony import explain

code = "4a"
code.isdigit() |> explain |> print

falsity
  str.isdigit('4a') returned False

Rule 2: truths as Python values

A truth passed to Python code is a Truth object. It defines __bool__, so it behaves correctly in Python conditions, all(), any(), filter(), sorting keys and anywhere else truthiness is used. [[settled]]

Code that requires an actual bool (json.dumps, isinstance(x, bool) checks, some C extensions) must convert explicitly with testimony.to_bool: [[settled]]

import json
from testimony import to_bool

passed = forall s in [61, 74, 88], s >= 50
print(json.dumps({"passed": to_bool(passed)}))

{"passed": true}

Rule 3: non-boolean comparisons

If a comparison's Python result is not a bool, it is returned unchanged and no truth is created. Libraries that overload comparisons, such as numpy and pandas, therefore work unmodified. [[settled]]

import numpy as np

a = np.array([3, -1, 4])
print(a[a > 0])

[3 4]

Applying and, or, not or because to such a result is subject to the open question in Section 7.8.

Rule 4: runtime requirements

The compiler is a standalone executable. Running a compiled program requires a Python 3 interpreter. The runtime module is written by the compiler, so no Python package needs to be installed. [[settled]]

Rule 5: tracebacks

Exceptions raised by a Verity program produce CPython tracebacks that refer to the generated Python file. [[settled]] Mapping tracebacks back to .ity source lines is planned but not scheduled.

Calling Verity from Python

A compiled Verity module is a Python module. Python code can import it and call its functions. Functions that return truths return Truth objects, which Python can test for truthiness, pass to to_bool, or render with explain. [[proposed]]

from validate import valid_username
from truth import explain

result = valid_username(form["username"])
if not result:
    log.info(explain(result))

Open questions

  • Non-truth operands of and/or. Python's name or "anonymous" idiom returns an operand. Options: (a) fall back to Python semantics when either operand is neither a truth nor a bool; (b) lift by Python truthiness; (c) reject at run time with TypeError. [[open]]
  • to_bool on non-truths. Whether to_bool accepts any value and applies Python truthiness, or only truths and bools. [[open]]
