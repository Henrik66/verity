Verity programs run on CPython and use Python libraries directly, and Python programs can use Verity's testimony. This section specifies the boundary in both directions.

Calling Python from Verity

Any module importable by the executing Python interpreter can be imported. Python functions, classes and values are used with ordinary call, attribute and subscription syntax. [[settled]]

import json
from statistics import mean

scores = json.loads("[61, 74, 88]")
print(mean(scores))

74.33333333333333

Rule 1: lifting Python booleans

A Python bool that appears where a truth is required is lifted into a truth with the same value. The positions that require a truth are: the operands of not, and and or (when the other operand is a truth or bool), the left operand of because, the body of a quantifier, the operand of assert, the arguments of all_of, and the argument of explain or to_json. [[settled]]

The lifted truth's testimony is a lifted node that quotes the source text of the expression and its result: [[settled]]

from testimony import explain

code = "4a"
print(explain(code.isdigit()))

falsity
  code.isdigit() returned False

When the runtime is used directly from Python, there is no source text, so the node reads <bool> returned False.

Rule 2: truths as Python values

A truth passed to Python code is a Truth object. It defines __bool__, so it behaves correctly in Python conditions, all(), any(), filter(), sorting keys and anywhere else truthiness is used. [[settled]]

Code that requires an actual bool (json.dumps, isinstance(x, bool) checks, some C extensions) must convert explicitly with testimony.to_bool, or serialize the testimony with to_json: [[settled]]

import json
from testimony import to_bool

passed = forall s in [61, 74, 88], s >= 50
print(json.dumps({"passed": to_bool(passed)}))

{"passed": true}

Rule 3: non-boolean comparisons

If a comparison's Python result is not a bool, it is returned unchanged and no truth is created. Libraries that overload comparisons, such as numpy and pandas, therefore work unmodified, and their results carry no testimony. [[settled]]

import numpy as np

a = np.array([3, -1, 4])
print(a[a > 0])

[3 4]

Rule 4: non-truth operands

If an operand of and or or is neither a truth nor a bool, the operation has Python's semantics and returns one of its operands, so name or "anonymous" works as in Python. not x on such a value is Python's not x, lifted. to_bool accepts any value and applies Python truthiness. [[settled]]

Rule 5: runtime requirements

The compiler is a standalone executable. Running a compiled program requires a Python 3.12 or later interpreter. The compiler writes its embedded runtime next to generated code, so .ity programs need no package installed. [[settled]]

Using testimony from Python

The runtime is published as the Python package verity-testimony, which provides the module testimony and the module string_ops. [[settled]]

$ pip install verity-testimony

Without the compiler, Python's and, or and not and its comparisons build no testimony. The library offers the same constructions as functions:

from testimony import all_of, check, explain, forall, reason

def valid_order(order):
    return all_of(
        check(order.qty, ">", 0, src="order.qty > 0").because(reason("qty.positive", "the quantity is positive")),
        forall(order.items, lambda item: check(item.price, ">=", 0, src="item.price >= 0"), name="item", src="order.items"),
    )

result = valid_order(order)
if not result:
    log.warning(explain(result))

The Python API is listed in Section 8.1. A compiled Verity module is also an ordinary Python module: Python code can import it and call its functions, which return Truth objects with full testimony.

The @testify decorator

[[proposed]] for milestone 4. @testify rewrites a plain Python predicate function at decoration time, as pytest rewrites asserts, so that its comparisons, and/or/not, and all()/any() over generator expressions build testimony:

from testimony import explain, testify

@testify
def all_positive(xs):
    return all(x > 0 for x in xs)

print(explain(all_positive([3, -1, 4])))

falsity
  counterexample: x = -1 (xs[1])
    x > 0: -1 <= 0

The pytest plugin

[[proposed]] for milestone 4. The package pytest-verity extends pytest's assertion rewriting so that a failing assert reports testimony. In particular, assert all(...) and assert any(...) over a generator report the counterexample or the absence of a witness, where pytest alone reports assert False.

    def test_prices():
>       assert all(item.price >= 0 for item in cart)
E       falsity
E         counterexample: item = Item(name='refund', price=-5) (cart[2])
E           item.price >= 0: -5 < 0

With --verity-json=PATH, the plugin writes one JSON Lines test record per test in the format of Section 10.2. When used with Hypothesis, the reported counterexample is Hypothesis's shrunk example, so it is minimal in Hypothesis's sense.

Tracebacks

verity run and verity test map tracebacks of uncaught exceptions to .ity file and line numbers. [[settled]] for milestone 3. Before that milestone, tracebacks refer to the generated Python file.
