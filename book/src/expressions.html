This section specifies Verity's expressions. Expressions not mentioned here (displays, comprehensions, subscriptions, slicing, attribute references, arithmetic, bitwise operators, conditional expressions) have Python's syntax and semantics.

Operator precedence

From highest (binds tightest) to lowest. Operators in the same row have equal precedence. [[proposed]] Where Verity shares an operator with Coconut, the relative order follows Coconut's.

Consequences worth noting:

  • x |> f == y parses as (x |> f) == y.
  • n % 2 == 0 because m parses as (n % 2 == 0) because m, and not p because m as (not p) because m.
  • p because m and q parses as (p because m) and q. The conformance examples parenthesize such operands anyway, and this document recommends doing so.
  • A quantifier's body extends as far right as possible, so a quantifier must be parenthesized to be piped: (forall x in xs, p) |> explain.

Primaries

primary   ::= atom trailer*
trailer   ::= "(" [arguments] ")" | "$" "(" [arguments] ")"
            | "[" subscripts "]" | "." NAME
atom      ::= NAME | NUMBER | STRING+ | "verity" | "falsity" | "None"
            | "(" [expression_list] ")" | list_display | set_display | dict_display

Atoms, calls, subscriptions and attribute references are as in Python. verity and falsity evaluate to truths with literal testimony (Section 5.1).

Partial application

partial   ::= primary "$" "(" [arguments] ")"

f$(a, b) evaluates f, a and b immediately and produces a callable g such that g(c, d) is f(a, b, c, d). Keyword arguments are supported, and keywords supplied at call time override those fixed by the partial. [[proposed]] The semantics match Python's functools.partial.

def power(base, exp) = base ** exp

two_to = power$(2)
print(two_to(10))
[1, 2, 3] |> map$(x -> x * 10) |> list |> print

1024
[10, 20, 30]

Coconut's ? placeholder for skipping positional arguments is not supported. [[open]]

Lambdas

lambda        ::= lambda_params "->" expression
lambda_params ::= NAME | "(" [NAME ("," NAME)* [","]] ")"

A lambda evaluates to a function whose body is the expression after ->. The body extends as far right as possible, so x -> x + 1 |> f is x -> ((x + 1) |> f). [[settled]] Default values, *args and **kwargs in lambda parameters are [[open]].

inc = x -> x + 1
add = (x, y) -> x + y
print(add(inc(1), 3))

Pipes

pipe      ::= compose ("|>" compose)*

x |> f evaluates x, then f, then calls f(x). Pipes associate left, so x |> f |> g is g(f(x)). [[settled]] Only |> is provided. Coconut's other pipe forms (<|, |*>, |?> and so on) are [[open]].

Composition

compose   ::= bit_or ("..>" bit_or)*

f ..> g evaluates both operands and produces a function h such that h(*args, **kwargs) is g(f(*args, **kwargs)). Composition associates left. [[settled]] for single-argument use. Forwarding of multiple arguments to f is [[proposed]].

shout = str.strip ..> str.upper ..> (s -> s + "!")
print(shout("  bluebell "))

BLUEBELL!

Comparisons

comparison ::= pipe (comp_op pipe)*
comp_op    ::= "==" | "!=" | "<" | ">" | "<=" | ">=" | "in" | "not" "in" | "is" | "is" "not"

A comparison a op b evaluates a and then b, and applies Python's comparison protocol. Then: [[settled]]

  • If the result r is a Python bool, the value of the comparison is a truth with the same truth value. Its testimony is a comparison node recording the source text of the whole comparison, both operand values and the relation that held (Section 5.2).
  • Otherwise, for example a numpy array or pandas Series, the value of the comparison is r, unchanged.

Comparison testimony for ==, !=, <, <=, > and >= is [[settled]]. For in, not in, is and is not it is [[proposed]], with the same form, e.g. 3 in xs: 3 not in [1, 2]. The meaning and testimony of chained comparisons such as a < b < c are [[open]]. Until they are settled, an implementation may reject chains.

Boolean operations

or_test     ::= and_test ("or" and_test)*
and_test    ::= because_test ("and" because_test)*
not_test    ::= "not" not_test | comparison

Operands of not, and and or must be truths. A Python bool operand is first lifted to a truth (Section 7.2). The behavior for operands that are neither, such as name or "anonymous", is [[open]].

  • not p is a truth with the opposite value. Its testimony wraps p's. [[settled]]
  • p and q evaluates p. If p is a falsity, the result is p's value and testimony, and q is not evaluated. Otherwise q is evaluated. A falsity q gives a falsity with q's testimony, and a verity gives a verity whose testimony lists both. [[settled]]
  • p or q is the dual: it short-circuits on the first verity, and a falsity lists every operand's refutation. [[settled]]

Unlike Python, and and or always produce a truth, never one of their operands. Exact testimony construction is given in Section 5.2.

Custom testimony: because

because_test ::= not_test ["because" not_test]

p because m evaluates p, which must be a truth or liftable bool, and yields a truth with the same value. Its testimony is a because node carrying str(m), with p's testimony as its child. [[settled]] m states the claim that holds when p is a verity. It renders after witnessed: or refuted:.

  • m is evaluated only if the testimony is observed (Section 5.4). [[proposed]] A program must therefore not rely on side effects in m.
  • because does not chain. p because a because b is a syntax error. [[proposed]]
from testimony import explain

is_even = n -> (n % 2 == 0 because f"{n} is even")
is_even(7) |> explain |> print

falsity
  refuted: 7 is even
    n % 2 == 0: 1 != 0

Quantifiers

quantifier ::= ("forall" | "exists") NAME "in" or_test "," expression

A quantifier evaluates its iterable expression once, then iterates over it in order. For each element it binds the name to the element in a new scope local to the quantifier, and evaluates the body, which must yield a truth or liftable bool. [[settled]]

  • forall stops at the first falsity and yields a falsity whose testimony is a counterexample node. If the iterable is exhausted, it yields a verity with a universal node.
  • exists stops at the first verity and yields a verity whose testimony is a witness node. If the iterable is exhausted, it yields a falsity with a no-element node.

Over an empty iterable, forall yields a verity and exists a falsity. Infinite iterables are permitted: evaluation terminates if and when a deciding element is found. The bound name must be a single identifier. Destructuring targets such as forall (k, v) in d.items(), ... are [[open]].

from testimony import explain

grid = [[1, 0], [0, 2], [3, 4]]
(forall row in grid, exists x in row, x == 0) |> explain |> print

falsity
  counterexample: row = [3, 4] (grid[2])
    no element of row satisfies x == 0

Conditional expressions

x if c else y has Python's semantics. c may be a truth. Its testimony is not observed by the conditional expression itself, so it is eligible for erasure (Section 5.5).
