A Verity program is read by the lexer as a sequence of tokens. Except where this section says otherwise, Verity's lexical structure is Python's.

Source files

  • Source files use the extension .ity. [[settled]]
  • Source text is UTF-8. A byte order mark is ignored. [[proposed]]
  • Each file is one module. Its module name is the file name without the extension. [[proposed]]

Line structure

A program is a sequence of logical lines, each terminated by a NEWLINE token. The rules are Python's: [[proposed]]

  • A physical line ends at \n, \r\n or \r.
  • Inside ( ), [ ] or { }, line breaks are ignored (implicit line joining).
  • A backslash at the end of a physical line, outside a string or comment, joins it with the next (explicit line joining).
  • A line containing only whitespace and an optional comment produces no tokens.
  • A comment starts with # outside a string literal and ends at the end of the physical line.

Indentation

Leading whitespace on a logical line determines its indentation level. The lexer keeps a stack of indentation widths, initially [0], and at the start of each logical line: [[settled]]

  1. If the width equals the top of the stack, no token is emitted.
  2. If it is greater, the width is pushed and one INDENT token is emitted.
  3. If it is smaller, widths are popped until it equals the top of the stack, emitting one DEDENT per pop. If no stack entry equals it, the lexer reports an error.

At end of input, one DEDENT is emitted for every entry above 0, followed by ENDMARKER.

Indentation may use spaces or tabs, but a file that indents with both reports an error, since their relative widths are ambiguous. [[proposed]]

Identifiers

Identifiers follow Python's rules: a letter or underscore followed by letters, digits or underscores, where "letter" includes Unicode characters with the XID_Start property and NFKC normalization applies. [[proposed]]

Standard library modules and functions are named in snake_case, for example list_ops, string_ops and testimony.explain. [[settled]]

Keywords

The following identifiers are reserved and cannot be used as ordinary names:

OriginKeywords
Verityverity falsity because forall exists
Coconutdata addpattern
Pythonand as assert break class continue def del elif else except finally for from global if import in is lambda None nonlocal not or pass raise return try while with yield

match and case are soft keywords. They are keywords only at the start of a match statement or case clause, as in Python. [[proposed]]

Whether Python keywords that Verity does not otherwise use (class, lambda, global, nonlocal, async, await) are supported, rejected or merely reserved is [[open]].

Literals

  • Numbers: integer, floating-point and imaginary literals, as in Python, including underscores and base prefixes.
  • Strings: Python string and bytes literals, including raw strings, triple-quoted strings and f-strings.
  • Truth: verity and falsity. These are the only truth literals. [[settled]]
  • None: None.

Operators and delimiters

Verity uses Python's operators and delimiters, plus these:

TokenNameUseSection
|>pipex |> f4.5
..>forward compositionf ..> g4.6
$partial applicationf$(x)4.3
->lambda arrowx -> x + 14.4

The tokenizer uses longest match, so ..> is one token, and |> is not | followed by >.

Python uses -> for return annotations. In Verity, -> after a parameter list in a def header is a return annotation. Elsewhere, it is a lambda arrow. [[proposed]]
