Roadmap

Updated 26 October 2026

Verity is Python 3.12 whose truth values explain themselves. The compiler is written in Rust and emits Python; the runtime, testimony.py, is embedded in the compiler and also published as the package verity-testimony. Milestones are built in order, one per working session, and a milestone counts as done only when every conformance example in its scope produces exactly its expected output.

Milestones

1

Runtime library done

runtime/testimony.py and runtime/string_ops.py: Truth, the testimony node kinds, comparisons, and/or/not, because, forall/exists, all_of, lifting, reason, secret/reveal, explain with developer and user audiences, to_json in the schema verity.testimony/0, bounds, to_bool and TestimonyError.

Result: 54 tests pass, including byte-for-byte rebuilds of all four examples; the verity-testimony wheel builds and installs. Not yet published to PyPI.

2

Tiny language and the CLI next

A hand-written lexer (with INDENT/DEDENT) and recursive-descent parser in Rust for literals, names, calls, attributes, arithmetic, comparisons, and/or/not, assignment, def/return, if/for/while, imports and f-strings, compiled to Python.

verity run, verity compile and verity check --json, with diagnostic E0101 for True/False and its machine-applicable fix. Non-bool comparisons (numpy, pandas) pass through, with a test.

3

Quantifiers, because, assert, verity test planned

forall/exists, because and reason, and assert raising TestimonyError. Source spans in testimony. verity test with --json. Python tracebacks mapped back to .ity lines.

4

pytest plugin and @testify planned

pytest-verity explains failing asserts with testimony, including all() and any() over generators, which pytest today reports as assert False. A @testify decorator gives plain Python predicate functions testimony without .ity files.

5

The rest of Python 3.12 planned

Classes and @dataclass, match, comprehensions, lambda, try/with and the remaining syntax.

6

Dual compilation (erasure) planned

Each function that returns a truth is compiled twice: an evidence version that builds testimony and a value version that computes plain booleans. A result that is only branched on calls the value version, so unobserved testimony costs nothing. Output must be identical with VERITY_NO_ERASE=1.

7

Tail calls with recorded tracebacks proposed

Python has no tail-call optimization, partly because erasing frames makes errors harder to locate. Verity can have both: the compiler rewrites a function whose return calls itself into a loop, so deep recursion no longer hits the recursion limit, and the loop keeps a call counter plus the arguments of the first and last few calls. If an error escapes, the traceback is rebuilt from that record:

f(n=100000, acc=1)          call 1
f(n=99999, acc=100000)      call 2
... 99,994 calls omitted
f(n=1, acc=...)             call 99,999
f(n=0, acc=...)             call 100,000  <- raised here
  • Direct self-calls in return position only, outside try/with and generators, where the name is never rebound or decorated.
  • Mutual recursion would need a trampoline and is left out at first.
  • Recording should cost nothing until an error is reported, in keeping with erasure.

Origin: suggested by a collaborator on 26 October 2026. Not part of the spec until adopted.
