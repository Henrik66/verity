Section 9Command-Line Interface

The verity executable compiles and runs Verity programs. The command names run and compile are Settled. Everything else in this section is Proposed.

9.1 Synopsis#

shell
$ verity run FILE.ity [ARG...]
$ verity compile FILE.ity [-o OUT.py]
$ verity --version
$ verity --help

9.2 verity run#

Compiles FILE.ity and executes it with Python. Arguments after the file name are passed to the program as sys.argv[1:], and sys.argv[0] is the source path.

  • Generated code and the runtime are written to a cache directory, __verity__/, next to the source file. The directory is reused across runs and can be deleted at any time.
  • The program's standard input, output and error are those of the verity process.
  • Imported .ity modules in the same directory are compiled on demand.

9.3 verity compile#

Compiles FILE.ity to Python without running it. By default the generated module is written to standard output. With -o OUT.py, it is written to OUT.py and the runtime module truth.py is written to the same directory.

shell
$ verity compile hello.ity -o build/hello.py
$ python3 build/hello.py

9.4 Exit status#

StatusMeaning
0Success. For run, the program exited with status 0.
1A compile error was reported.
2Invalid command-line usage.
otherFor run, the exit status of the Python process.

9.5 Diagnostics#

Errors are written to standard error, one per diagnostic, in the form:

output
hello.ity:3:14: error: expected ')' to close '(' at 3:5

Line and column numbers are 1-based. Columns count Unicode scalar values.

9.6 Environment#

VariableEffect
VERITY_PYTHONPython interpreter used by run. Default: python3 on the PATH.
VERITY_NO_ERASEIf set to 1, disables testimony erasure. This is for checking that erasure does not change output.
