Chapter 6Data and Patterns

Programs are mostly about data, and functional languages have a particular way of describing it. You declare the possible shapes a value can take, then write functions that handle each shape. Verity provides data declarations for the first part and pattern matching for the second.

6.1 Data types#

A data declaration defines a new kind of value with named fields:

verity
data Circle(r)
data Rect(w, h)
data Square(side)

c = Circle(1)
print(c)
print(c.r)
output
Circle(r=1)
1

Data values are immutable. Once built, their fields cannot change. To "modify" one, you build a new value. Data values also compare by content, so Rect(2, 3) == Rect(2, 3). Together these make data values safe to share, cache and use as dictionary keys.

A group of data declarations that are used together, like the three shapes above, is called an algebraic data type. A shape is a circle, or a rectangle, or a square, and each of those has its own fields.

6.2 Functions by cases#

To compute the area of a shape, we need different formulas for different shapes. Verity lets you write each case as its own definition, with a pattern in place of a parameter:

verity
def area(Circle(r)) = 3.14159 * r ** 2
addpattern def area(Rect(w, h)) = w * h
addpattern def area(Square(s)) = s * s

The pattern Circle(r) matches any Circle and binds its field to the name r. addpattern def adds another case to an existing function rather than replacing it. When area is called, the cases are tried in the order they were defined, and the first one whose pattern matches runs. If none matches, the call raises a MatchError.

Patterns can also be literal values, which makes recursive definitions read like their mathematical description:

verity
def factorial(0) = 1
addpattern def factorial(n) = n * factorial(n - 1)

Order matters here. If the cases were swapped, the general case n would match everything, and the base case would never run.

6.3 The match statement#

When the cases belong inside one function body, use match. Its syntax is Python's structural pattern matching:

verity
def describe(shape):
    match shape:
        case Circle(r):
            return f"a circle of radius {r}"
        case Rect(w, h) if w == h:
            return f"a rectangle that is secretly a {w} by {w} square"
        case Rect(w, h):
            return f"a {w} by {h} rectangle"
        case _:
            return "some other shape"

A case can carry a guard (if w == h), which must hold for the case to be chosen. The pattern _ matches anything. Here the guard is only used to choose a branch, so its testimony is erased.

6.4 Deciding claims by cases#

Pattern matching and testimony fit together well. A predicate decided by cases can give a different kind of evidence in each case: a real comparison where there is something to compare, and a stated reason where the answer follows from the shape alone. This is examples/shapes.ity from the Verity repository:

verity
# Algebraic data types, pattern matching, and truths that testify.
from testimony import explain

data Circle(r)
data Rect(w, h)
data Square(side)

def area(Circle(r)) = 3.14159 * r ** 2
addpattern def area(Rect(w, h)) = w * h
addpattern def area(Square(s)) = s * s

def is_square(shape):
    match shape:
        case Square(_):
            return verity because "it was built as a Square"
        case Rect(w, h):
            return w == h
        case _:
            return falsity because f"{shape} is a rectangle"

shapes = [Circle(1), Rect(2, 3), Square(4), Rect(5, 5)]

shapes |> map$(area) |> list |> print

for s in shapes:
    print(f"{s}: {explain(is_square(s))}")

(forall s in shapes, area(s) > 3) |> explain |> print
output
[3.14159, 6, 16, 25]
Circle(r=1): falsity
  refuted: Circle(r=1) is a rectangle
Rect(w=2, h=3): falsity
  w == h: 2 != 3
Square(side=4): verity
  witnessed: it was built as a Square
Rect(w=5, h=5): verity
  w == h: 5 == 5
verity
  all 4 elements of shapes satisfy area(s) > 3

Look at the circle's case. Its claim is that the shape is a rectangle, since squareness is a property only rectangles can have. Its refutation is the plain fact that a circle isn't one. Each rectangle's testimony is a real comparison of its sides.

6.5 Recursive data#

A data type can refer to itself, which is how trees are built. Here is a binary search tree with two shapes, an empty Leaf and a Node holding a value and two subtrees:

verity
from functools import reduce

data Leaf()
data Node(left, value, right)

def insert(tree, x):
    match tree:
        case Leaf():
            return Node(Leaf(), x, Leaf())
        case Node(l, v, r) if x < v:
            return Node(insert(l, x), v, r)
        case Node(l, v, r):
            return Node(l, v, insert(r, x))

def to_list(Leaf()) = []
addpattern def to_list(Node(l, v, r)) = to_list(l) + [v] + to_list(r)

reduce(insert, [5, 2, 8, 1], Leaf()) |> to_list |> print
output
[1, 2, 5, 8]

insert never changes a tree. It returns a new tree that shares every untouched subtree with the old one. Because data values are immutable, sharing is always safe.

6.6 Exercises#

Exercise: perimeter ★

Define perimeter for Circle, Rect and Square using def and addpattern def.

Exercise: swapped cases ★

What happens when you call factorial(3) if its two cases are defined in the opposite order?

Exercise: tree membership ★★

Write contains(tree, x) for the search tree in Section 6.5. Return a truth whose testimony tells the caller something useful in both outcomes. For example, a falsity might say which leaf the search reached.

Exercise: a triangle ★★

Add data Triangle(a, b, c) (side lengths) to the shapes example. Extend area using Heron's formula and decide what is_square should say about it. Write the new lines of output.

Exercise: when patterns fail ★★★

A call that matches no pattern raises MatchError. Could a failed match instead produce testimony, listing each case and why its pattern didn't match? When would that be useful, and when would it be noise?
