Preface

This book is about Verity, a small functional language that compiles to Python. It is also about one idea that Verity is built around: a program's yes-or-no answers should come with reasons attached.

Who this book is for#

The book assumes you can already program, ideally in Python. You should be comfortable with functions, lists, loops and conditionals. You do not need any background in functional programming. Lambdas, pipes, algebraic data types and pattern matching are each introduced from scratch.

If you already know Coconut, much of the syntax will be familiar, and you can skim Chapters 5 and 6. The parts that are new everywhere are Chapter 3 on testimony and Chapter 4 on quantifiers.

The status of Verity#

Verity is in early design, and this edition is written ahead of the implementation. The language described here is the one the compiler is being built to accept. The example programs and their expected outputs double as the project's acceptance tests: a milestone counts as done only when its examples produce exactly the output printed in this book.

That means the book is also a design document. Where the design is unsettled, the text says so in a design note:

Design note

Design notes mark open questions and proposals. Treat what they say as tentative until the language's spec (the repository's CLAUDE.md) adopts it.

Conventions#

Verity source code appears in blocks with a green edge:

verity
# This is Verity.
greeting = "hello" |> str.upper
print(greeting)

Output appears in blocks with a yellow edge. When a truth value is printed with explain, the output shows its testimony indented beneath it:

output
HELLO

Generated Python, which appears mostly in Chapter 8, has a blue edge. Shell commands start with $:

shell
$ verity run hello.ity

Verity source files use the .ity extension.

Exercises#

Each chapter ends with exercises, rated by difficulty:

  • ★: a quick check that you followed the chapter.
  • ★★: needs some thought or a short program.
  • ★★★: open-ended, or a design question without a settled answer.

Until the compiler exists, work the exercises on paper. Predicting a program's testimony by hand is good practice anyway, because it is exactly what the compiler and runtime will have to do.

Acknowledgments#

Verity's surface syntax comes almost entirely from Coconut, Evan Hubinger's functional superset of Python. The structure of this book (chapters that build up a language, with rated exercises) is modeled on Cornell's CS 3110 textbook, OCaml Programming: Correct + Efficient + Beautiful.
