Chapter 4Quantifiers

Python has all() and any(), and both are perfectly blind. When all(...) returns False, some element broke the rule, but you don't learn which. Verity's quantifiers, forall and exists, return truths that keep the element that decided the answer.

4.1 Universal claims: forall#

The syntax is:

verity
forall x in xs, body

It checks body for each element x of the iterable xs, in order. The body is any truth-valued expression that can use x.

  • If some element refutes the body, the result is a falsity. Its testimony is a counterexample: line naming the element and its position, with the body's refutation nested beneath. forall stops at the first counterexample.
  • If every element satisfies the body, the result is a verity whose witness says so.
verity
from testimony import explain

primes = [2, 3, 5, 7, 11, 13]
(forall p in primes, p % 2 == 1) |> explain |> print
(forall p in primes, p > 1) |> explain |> print
output
falsity
  counterexample: p = 2 (primes[0])
    p % 2 == 1: 0 != 1
verity
  all 6 elements of primes satisfy p > 1

A counterexample is the most useful thing a failed universal claim can give you, and it is exactly what a boolean throws away.

4.2 Existential claims: exists#

exists has the same shape and the mirror-image behavior:

verity
exists x in xs, body
  • If some element satisfies the body, the result is a verity with a witness: line naming that element. exists stops at the first witness.
  • If no element does, the result is a falsity whose refutation says so.
verity
from testimony import explain

primes = [2, 3, 5, 7, 11, 13]
(exists p in primes, p > 10) |> explain |> print
(exists p in primes, p > 100) |> explain |> print
output
verity
  witness: p = 11 (primes[4])
    p > 10: 11 > 10
falsity
  no element of primes satisfies p > 100

This mirrors constructive logic, where a proof of "there exists an x such that P(x)" must actually exhibit an x. A verity from exists doesn't just tell you something qualifies. It hands you the thing.

4.3 A worked example#

This is examples/counterexample.ity from the Verity repository, one of the programs the compiler must reproduce exactly:

verity
# forall finds a counterexample; exists finds a witness.
from testimony import explain

primes = [2, 3, 5, 7, 11, 13]

all_odd = forall p in primes, p % 2 == 1
has_big = exists p in primes, p > 10

all_odd |> explain |> print
has_big |> explain |> print

if not all_odd:
    print("not every prime is odd, and Verity can tell you why")
output
falsity
  counterexample: p = 2 (primes[0])
    p % 2 == 1: 0 != 1
verity
  witness: p = 11 (primes[4])
    p > 10: 11 > 10
not every prime is odd, and Verity can tell you why

A quantifier's result is an ordinary truth, so it can be stored in a variable, tested with if and negated with not.

4.4 Nesting and combining#

The body of a quantifier can be any truth-valued expression, including another quantifier, an and, or a because. Testimony nests accordingly:

verity
from testimony import explain

grid = [[1, 0], [0, 2], [3, 4]]

# Does every row contain a zero?
(forall row in grid, exists x in row, x == 0) |> explain |> print
output
falsity
  counterexample: row = [3, 4] (grid[2])
    no element of row satisfies x == 0

Read it top down: the claim fails, here is the row that fails it, and here is why that row fails. Combining a quantifier with because gives the same story in domain language:

verity
def sorted_ascending(xs) = (
    forall i in range(len(xs) - 1),
        (xs[i] <= xs[i + 1] because f"{xs[i]} comes no later than {xs[i + 1]}")
)

4.5 Details and edge cases#

Scope of the body

The body extends as far to the right as possible. To pipe a quantifier's result somewhere, wrap the quantifier in parentheses, as the examples above do:

verity
(forall s in shapes, area(s) > 3) |> explain |> print

Without the parentheses, the pipe would become part of the body.

Empty collections

Over an empty collection, forall is a verity: there is no counterexample, so the claim holds vacuously. exists is a falsity, because there is nothing to exhibit. The testimony says so plainly:

output
verity
  all 0 elements of xs satisfy x > 0

Positions

When the collection is a name, the position is written as an index into it, like primes[4].

Design note: positions in general iterables

Quantifiers accept any iterable, including generators and range, where "index into the source" may not make sense. The proposal is to fall back to (element 4) whenever the collection expression is not a simple name. Infinite iterables are allowed as well. exists over an infinite generator stops at its first witness, while forall stops at its first counterexample or runs forever.

4.6 Exercises#

Exercise: first counterexample ★

Write the output of (forall n in [4, 8, 9, 10, 15], n % 2 == 0) |> explain |> print. Why does 15 not appear?

Exercise: no zero ★

Change grid in Section 4.4 so that the nested claim becomes a verity. What does its witness look like?

Exercise: sortedness ★★

Using sorted_ascending from Section 4.4, write the full explain output for [1, 5, 3, 4], following the position rule in the design note. Does the output point you at the bug?

Exercise: all counterexamples ★★★

forall stops at the first counterexample. Sometimes you want all of them, for example when validating every row of a spreadsheet. Sketch a standard library function or a syntax for that. How should its testimony print, and how would it interact with erasure?
