Section 1Overview

Verity is Python whose truth values explain themselves. When a check fails, a Verity program can say which comparison, element or claim decided it, both as text for people and as JSON for tools and agents. It compiles to Python and runs on CPython.

1.1 Summary#

  • Syntax. Python 3.12, plus four additions: the truth literals verity and falsity, p because m, the quantifiers forall and exists, and an assert that keeps testimony. Anyone, person or model, who can write Python can write Verity. Settled
  • Truth values. The type truth has exactly two constructors, verity and falsity. Settled
  • Testimony. Every truth carries testimony: a verity carries a witness and a falsity a refutation. Comparisons, and, or, not, forall, exists, because and all_of construct it automatically. Settled
  • Machine-readable. Testimony serializes to a published JSON schema. Compiler diagnostics have stable codes and machine-applicable fixes. verity check, run and test emit JSON Lines with --json. Settled
  • No cost when unused. Testimony that nobody observes is never built: a check used only as an if condition compiles to a plain Python boolean expression. Settled
  • A library too. The runtime is the Python package verity-testimony, so Python programs and test suites can use testimony without writing .ity files. Settled

1.2 Example#

verity
from testimony import explain

primes = [2, 3, 5, 7, 11, 13]

all_odd = forall p in primes, p % 2 == 1
has_big = exists p in primes, p > 10

print(explain(all_odd))
print(explain(has_big))

if not all_odd:
    print("not every prime is odd, and Verity can tell you why")
output
falsity
  counterexample: p = 2 (primes[0])
    p % 2 == 1: 0 != 1
verity
  witness: p = 11 (primes[4])
    p > 10: 11 > 10
not every prime is odd, and Verity can tell you why

This program is examples/counterexample.ity, one of the conformance examples.

1.3 Why#

A failed check in most languages says only that it failed. pytest, for example, explains a failing comparison but reports a failing assert all(x > 0 for x in xs) as assert False. A person can open a debugger. An agent that wrote the code and is trying to fix it has only the output.

Verity's answer is to make the explanation part of the value. A falsity from forall names the element that failed and where it was; a falsity from a validation function names the rule, its stable reason ID and a hint for fixing it. The same tree renders as text for a person and as JSON for a program, so an agent can read why a check failed, change the code and check again without guessing.

1.4 Design goals#

  1. Checks explain themselves. A falsity identifies the comparison, element or claim that decided it, with the values involved.
  2. Readable by programs. Every explanation, diagnostic and test result has a documented machine-readable form with stable identifiers, and output is deterministic.
  3. Python, not a new syntax. Verity adds as little syntax as possible to Python, so existing knowledge of Python, in people and in language models, carries over.
  4. No cost when unused. Programs that never observe testimony run as fast as the equivalent Python.
  5. Honest. Testimony distinguishes what was computed from what was claimed, hides secrets, and stays bounded in size.

1.5 Non-goals#

  • Proof. Testimony explains what a program evaluated. It does not verify claims (Section 5.12).
  • Authorization engines. Explaining an access decision can reveal policy to the person it was denied to. Policy engines built for that purpose are a better fit.
  • Data-frame validation. Vectorised comparisons on numpy arrays and pandas series pass through without testimony. Data-quality tools already report per-row failures.

1.6 Execution model#

file.ity→ verity (Rust)→ Python module + testimony.py→ CPython
  • The compiler, verity, is a standalone executable written in Rust. Settled
  • A compilation unit is one source file. Each .ity file produces one Python module. Settled
  • The runtime, testimony.py with string_ops.py, is embedded in the compiler and written next to generated code, so .ity programs need no install and always run with the matching runtime. The same runtime is published as the package verity-testimony for use from Python. Settled
  • Programs are executed by CPython 3.12 or later. Proposed

See Section 9 for the command-line interface, Section 10 for the machine interface and Section 11 for the compiler's internals.

1.7 Differences from Python#

TopicPythonVerity
Boolean literalsTrue, Falseverity, falsity, of type truth, carrying testimony. True/False are a compile error with an automatic fix.
ComparisonsReturn bool (or any object)Return a truth when Python would return a bool; otherwise the result passes through unchanged
and, or, notReturn one of the operandsReturn a truth combining the operands' testimony when the operands are truths or bools; Python semantics otherwise
Quantifiersall(), any() return boolAlso forall, exists expressions, which name the deciding element
assertRaises AssertionError; removed under -ORaises TestimonyError carrying the falsity; never removed

Earlier designs

Before October 2026 Verity borrowed Coconut's syntax (-> lambdas, |> pipes, $ partial application, data and addpattern). It was dropped so that people and language models who know Python can write Verity without learning new operators. Python already provides lambda, match and data classes.
