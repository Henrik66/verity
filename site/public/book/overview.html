Section 1Overview

Verity is a functional programming language that compiles to Python. Its truth values carry evidence for why they are true or false.

1.1 Summary#

  • Syntax. Python's statement and expression syntax, extended with Coconut's functional forms: x -> x + 1 lambdas, |> pipes, f$(args) partial application, ..> composition, match, data types, and pattern-matched def extended by addpattern def. Settled
  • Truth values. The type truth has exactly two constructors, verity and falsity. Settled
  • Testimony. Every truth carries testimony: a verity carries a witness and a falsity a refutation. Comparisons, and, or, not, forall, exists and because construct testimony automatically. Settled
  • Erasure. Testimony that is never observed is not constructed. A truth used only as a branch condition compiles to a plain Python boolean expression. Settled
  • Target. Each .ity file compiles to one Python module that runs on CPython and imports a small runtime module. Settled

1.2 Example#

verity
from testimony import explain

primes = [2, 3, 5, 7, 11, 13]

all_odd = forall p in primes, p % 2 == 1
has_big = exists p in primes, p > 10

all_odd |> explain |> print
has_big |> explain |> print

if not all_odd:
    print("not every prime is odd, and Verity can tell you why")
output
falsity
  counterexample: p = 2 (primes[0])
    p % 2 == 1: 0 != 1
verity
  witness: p = 11 (primes[4])
    p > 10: 11 > 10
not every prime is odd, and Verity can tell you why

This program is examples/counterexample.ity, one of the conformance examples.

1.3 Design goals#

  1. Truth values explain themselves. A falsity identifies the comparison, element or claim that decided it, together with the values involved.
  2. No cost when unused. Programs that never observe testimony run as fast as the equivalent Python.
  3. Python compatibility. Any Python module can be imported, and compiled Verity modules can be imported from Python.
  4. Functional by default. Short function definitions, pipelines, algebraic data types and pattern matching are the primary style.
  5. Readable output. Generated Python stays structurally close to its source.

1.4 Execution model#

file.ity→ verity (Rust)→ Python module + truth.py→ CPython
  • The compiler, verity, is a standalone executable written in Rust. Settled
  • A compilation unit is one source file. Each .ity file produces one Python module. Settled
  • Generated modules import the runtime module truth.py, which is embedded in the compiler binary and written next to generated code. Settled
  • Programs are executed by CPython. The minimum supported Python version is not yet fixed. Open

See Section 9 for the command-line interface and Section 10 for the compiler's internals.

1.5 Differences from Python and Coconut#

TopicPythonVerity
Boolean valuesTrue, False of type boolverity, falsity of type truth, carrying testimony
ComparisonsReturn bool (or any object)Return a truth when Python would return a bool; otherwise the result passes through unchanged (Section 7.4)
and, orReturn one of the operandsReturn a truth combining the operands' testimony
Quantifiersall(), any() return boolforall, exists expressions return a truth naming the deciding element
Function definitionsdef blocks, lambdaAdditionally def f(x) = expr, x -> expr, pattern parameters and addpattern def

Relative to Coconut, Verity adopts only the functional forms listed in the summary. Other Coconut operators and features (for example, the |*> family of pipes, <.., :: and the ? placeholder in partial application) are not part of Verity. Whether any will be added is Open.

Lambda arrow

Current Coconut documentation describes -> lambdas as deprecated in favor of =>. Verity's specification uses ->, and this document follows the specification.
