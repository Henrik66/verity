Chapter 2The Basics

This chapter covers the everyday parts of Verity: running a program, values, definitions, truth values, control flow and imports. If you know Python, most of it will look familiar. The differences are few, but they matter.

2.1 Running a program#

A Verity program is a text file ending in .ity. Save this as hello.ity:

verity
print("hello, garden")

and run it:

shell
$ verity run hello.ity
output
hello, garden

verity run compiles the file to Python and runs it immediately. To see the Python it generates instead, use verity compile:

shell
$ verity compile hello.ity

The generated code is meant to be readable. Looking at it is a good way to understand what a Verity feature really does.

2.2 Values and expressions#

Verity's values are Python's values: integers, floats, strings, lists, tuples, dictionaries and sets, written the same way and supporting the same operations.

verity
# Comments start with a hash, as in Python.
answer = 6 * 7
pi_ish = 22 / 7
name = "Ada"
primes = [2, 3, 5, 7]
point = (3, 4)
ages = {"ada": 36, "alan": 41}

print(f"{name} is {ages['ada']}; the answer is {answer}")
output
Ada is 36; the answer is 42

Strings support Python's f-strings, slicing and methods. Lists support indexing, slicing and comprehensions. Arithmetic follows Python's rules, including / for true division, // for floor division and ** for powers.

2.3 Definitions#

A name is bound with =, as in Python. Functions can be defined in two ways. The short form, borrowed from Coconut, defines a function whose body is a single expression:

verity
def square(x) = x * x
def hypotenuse(a, b) = (square(a) + square(b)) ** 0.5

print(hypotenuse(3, 4))
output
5.0

The long form is Python's block syntax, for functions that need several statements:

verity
def describe(n):
    kind = "even" if n % 2 == 0 else "odd"
    return f"{n} is {kind}"

Prefer the short form when it fits. Verity code tends toward small functions that compute a value rather than larger ones that perform a sequence of steps. The short form makes that style the easy one.

2.4 Truth values#

Verity's truth type is truth, and its two values are verity and falsity. Comparisons produce truths:

verity
from testimony import explain

x = 7
(x > 3) |> explain |> print
(x == 10) |> explain |> print
output
verity
  x > 3: 7 > 3
falsity
  x == 10: 7 != 10

Every truth carries testimony, and explain from the standard library module testimony turns a truth into text. The first line is the truth itself, and the indented lines below are its testimony. For a comparison, the testimony quotes the source expression, then shows the values that were actually compared, using the operator that held. x == 10 was refuted because 7 != 10. Chapter 3 is devoted to testimony.

Verity source spells its truth values verity and falsity, never True and False. For what happens when Python libraries hand back True/False, see Chapter 7.

2.5 Conditionals and loops#

Truths drive if, elif, else and while exactly as Python booleans do. Conditional expressions work too:

verity
def grade(score):
    if score >= 90:
        return "A"
    elif score >= 80:
        return "B"
    else:
        return "keep growing"

def sign(n) = "negative" if n < 0 else "non-negative"

When a truth is only used to choose a branch, as in grade, its testimony is never observed. The compiler erases it, and the comparison compiles to a plain Python comparison.

for loops and comprehensions are also available. Verity is functional in style rather than in law. Loops are fine at the edges of a program, such as printing results, while the core is best written as functions over values. The examples in this book follow that pattern.

verity
for name in ["ada", "alan", "grace"]:
    print(name.title())

squares = [n * n for n in range(5)]

2.6 Imports and the standard library#

Verity's import statement is Python's, and it can import Python modules directly:

verity
import math
from statistics import mean

print(math.sqrt(2))
print(mean([1, 2, 3, 4]))

Verity's own standard library modules use snake_case names:

ModulePurpose
testimonyWorking with testimony, starting with explain.
string_opsString predicates and helpers whose truths testify, such as string_ops.is_alnum.
list_opsList helpers in a functional style.

Design note: the standard library

Only the module names and a few functions used in this book (testimony.explain, string_ops.is_alnum) are settled. Their full contents will be designed alongside the language milestones.
