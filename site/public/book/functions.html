Chapter 5Functions and Pipelines

Functions are values in Verity, as they are in Python. What Verity adds, by way of Coconut, is lighter syntax for building functions and plugging them together. This chapter covers lambdas, pipes, partial application and composition, and how they combine with testimony.

5.1 Lambdas#

A lambda is written with an arrow:

verity
inc = x -> x + 1
add = (x, y) -> x + y

print(inc(41))
print(add(2, 3))
output
42
5

A lambda's body is a single expression. For anything longer, give the function a name with def. Lambdas are most useful as arguments:

verity
words = ["fern", "moss", "oak", "bluebell"]
print(sorted(words, key=w -> len(w)))
output
['oak', 'fern', 'moss', 'bluebell']

5.2 Pipes#

The pipe operator |> passes the value on its left to the function on its right:

verity
x |> f        # means f(x)
x |> f |> g   # means g(f(x))

Nested calls read inside out, so print(list(map(f, xs))) starts with the innermost call. A pipeline reads in the order things happen:

verity
[3, 1, 2] |> sorted |> reversed |> list |> print
output
[3, 2, 1]

You have already seen the most common Verity pipeline, t |> explain |> print: take a truth, render its testimony, print it.

5.3 Partial application#

Pipes pass exactly one argument, but many useful functions take more. Partial application, written f$(args), fixes some of a function's arguments now and leaves the rest for later:

verity
def power(base, exp) = base ** exp

two_to = power$(2)       # exp still missing
print(two_to(10))

[1, 2, 3] |> map$(x -> x * 10) |> list |> print
output
1024
[10, 20, 30]

map$(f) is the idiom to remember. map needs a function and an iterable, so fixing the function produces something that takes the iterable, which is exactly what a pipe supplies.

5.4 Composition#

Composition joins two functions into one. Verity uses Coconut's forward composition operator ..>, which reads left to right like a pipe:

verity
(f ..> g)(x)   # means g(f(x))

A pipe applies functions to a value now. Composition builds a new function to apply later:

verity
normalize = str.strip ..> str.lower
shout = normalize ..> str.upper ..> (s -> s + "!")

print(shout("  Bluebell "))
output
BLUEBELL!

5.5 Predicates that testify#

A predicate is a function that returns a truth. In Verity, predicates are a natural place for because. Write the claim once in the predicate, and every use inherits it:

verity
from testimony import explain

is_even = n -> (n % 2 == 0 because f"{n} is even")

xs = [2, 4, 5]
(forall n in xs, is_even(n)) |> explain |> print
output
falsity
  counterexample: n = 5 (xs[2])
    refuted: 5 is even
      n % 2 == 0: 1 != 0

The testimony stacks up: the quantifier found its counterexample, the predicate stated its claim, and the comparison gave the raw values. Each layer was written once, in the place it belongs.

Predicates compose too. Here a predicate is combined with a pipeline that filters a list:

verity
both = (p, q) -> (x -> p(x) and q(x))
positive = n -> (n > 0 because f"{n} is positive")
positive_even = both(positive, is_even)

[-2, 4, 7, 12] |> filter$(positive_even) |> list |> print
output
[4, 12]

Here filter only uses the truths as conditions, so their testimony is never observed and the compiler erases it (see Chapter 8).

5.6 A note on style#

Pipes and composition can be overused. A good rule of thumb: use a pipe when the data flows through three or more steps, and a plain call when it doesn't. print(x) is clearer than x |> print on its own. Name intermediate functions when the name tells the reader something the code doesn't.

5.7 Exercises#

Exercise: rewrite as a pipeline ★

Rewrite print(sum(map(lambda x: x * x, range(10)))) as a Verity pipeline using a lambda and partial application.

Exercise: compose a slug ★★

Using ..>, build a function slug that strips whitespace, lowercases, and replaces spaces with hyphens, so that slug(" Wild Garlic ") is "wild-garlic".

Exercise: predicate testimony ★★

Write the explain output of (forall n in [-2, 4], positive(n)), using positive from Section 5.5.

Exercise: testimony through filter ★★★

filter discards the truths it computes. Design a list_ops function that partitions a list into the elements that pass and fail a predicate and keeps each failure's refutation. What type does it return?
