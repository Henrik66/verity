Section 3Data Model

Every value in a running Verity program is a Python object. This section describes the objects Verity adds: truths, testimony, data values and pattern-matching functions.

3.1 Objects#

Verity has no object model of its own. Integers, strings, lists, functions, modules and all other values are the corresponding Python objects, with Python's identity, type and mutability rules. Settled

3.2 The truth type#

truth is the type of truth values. Settled

  • It has exactly two constructors: verity (true) and falsity (false).
  • Every truth carries a testimony tree (Section 5). A verity's testimony is called its witness, and a falsity's its refutation.
  • At run time, truths are instances of the runtime class Truth (Section 8.2).

The following properties are Proposed:

  • Truths are immutable.
  • bool(t) is True for a verity and False for a falsity. Truths are accepted anywhere Python accepts a condition.
  • Equality and hashing consider only the truth value, never the testimony. Two verities with different witnesses are equal.
  • str(t) is "verity" or "falsity". repr(t) is the same, and testimony is shown only by testimony.explain.
  • truth is not a subclass of Python's bool or int, so arithmetic on truths raises TypeError.

3.3 Testimony#

A testimony is a finite tree of nodes. Each node has a kind, the data for that kind (source text, values, a message, a position) and an ordered list of children. The node kinds, how they are constructed and how they are rendered are specified in Section 5. Settled

Testimony holds references to the values it mentions, not copies. Rendering uses repr() of those values at render time. Proposed

3.4 Data values#

A data declaration (Section 6.5) defines a class whose instances are data values.

  • Instances are immutable. Their fields cannot be reassigned. Settled
  • Instances are constructed positionally in field order: Rect(2, 3). Construction by keyword, Rect(w=2, h=3), is also permitted. Proposed
  • Fields are readable as attributes: Rect(2, 3).w == 2.
  • repr is Name(field=value, ...), for example Circle(r=1). Settled
  • Equality is structural: same class and equal fields. Hashing is consistent with equality. Proposed
  • Data values can be matched by class patterns (Section 6.4).
verity
data Rect(w, h)

r = Rect(2, 3)
print(r)
print(r.w * r.h)
print(r == Rect(2, 3))
output
Rect(w=2, h=3)

3.5 Functions#

Functions are Python function objects. Two forms carry additional structure:

  • Pattern-matching functions are defined with pattern parameters and extended with addpattern def (Section 6.3). Calling one tries its cases in definition order. If no case matches, it raises MatchError.
  • Partial applications, f$(args), are callables that hold f and the supplied arguments (Section 4.3).

MatchError is a subclass of Python's Exception, provided by the runtime. Proposed
