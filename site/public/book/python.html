Chapter 7Living with Python

Verity compiles to Python and runs on CPython, so any Python library is one import away. Python code knows nothing about testimony, though. This chapter covers the rules at the boundary: what happens when Python values meet Verity truths, and the reverse.

7.1 Using Python libraries#

Importing works exactly as in Python, and so does calling the imported functions:

verity
import json
from pathlib import Path
from statistics import mean

scores = Path("scores.json").read_text() |> json.loads
print(mean(scores))

The compiled program is ordinary Python, so it can also be imported from Python. A Python project can adopt Verity one module at a time.

7.2 Rule 1: Python booleans become truths#

When Python code hands back a plain True or False where Verity expects a truth, the runtime lifts it into a truth. Python can't explain its answer, so the testimony records what Verity does know: the call that produced the boolean, with its argument values:

verity
from testimony import explain

code = "4a"
code.isdigit() |> explain |> print
output
falsity
  str.isdigit('4a') returned False

Lifted testimony is thin, but it is honest. For richer testimony, wrap the check in a Verity predicate with because, or use the standard library's testifying versions, such as those in string_ops.

7.3 Rule 2: Truths work as Python booleans#

Going the other way, a Verity truth behaves like a Python boolean in all the usual places: if, while, all(), any(), filter(), sorted(key=...) and so on. Python libraries that just test a value's truthiness will never notice the difference.

A few places insist on an actual bool. Examples include json.dumps, strict isinstance(x, bool) checks and some C extensions. For those, convert explicitly with to_bool:

verity
import json
from testimony import to_bool

passed = forall s in scores, s >= 50
json.dumps({"passed": to_bool(passed)}) |> print
output
{"passed": true}

(This assumes every score is at least 50.)

7.4 Rule 3: Non-boolean comparisons pass through#

Some libraries redefine comparison operators to return something other than a boolean. In numpy, array > 0 compares element by element and returns an array. In pandas, df["age"] > 30 returns a Series used to filter rows. Wrapping those results in truths would break the libraries.

So the rule is: when a comparison's result is not a bool, Verity returns it untouched. Everything works as it does in Python:

verity
import numpy as np

a = np.array([3, -1, 4])
print(a[a > 0])
output
[3 4]

This is easy to get wrong in an implementation, so it is pinned down by tests from the first compiler milestone onward.

7.5 Rule 4: Python is required to run programs#

The verity compiler is a standalone Rust binary. Running a compiled program needs python3 on the machine, just as running a Python program does. The runtime module, truth.py, is written out by the compiler, so there is no Python package to install.

7.6 Rule 5: Tracebacks point at generated Python (for now)#

When a Verity program raises an exception, the traceback CPython prints refers to lines in the generated Python file, not in your .ity source. The generated code is designed to stay close to the source, so the mapping is usually easy to follow by eye. Proper source mapping is planned but not yet scheduled.

7.7 Open questions#

Design note: and/or on non-truths

In Python, name or "anonymous" returns a value, not a boolean, and is a common idiom. When Verity rewrites or into a testimony-building call, what should happen if an operand isn't a truth? One proposal is to fall back to Python's semantics whenever either operand is not a truth or a bool. That keeps the idiom working, but it means or returns different kinds of values depending on its inputs.

Design note: in, is and chained comparisons

Should x in xs and x is None testify like comparisons, with output such as 3 in xs: 3 not in [1, 2]? And how should a chained comparison like 0 <= x < 10 print: as one line, or as an all of: over its two halves? Both are proposed to testify, but neither format is settled.

7.8 Exercises#

Exercise: lifted testimony ★

What testimony would "hello".startswith("he") carry when it is passed to explain?

Exercise: upgrade the evidence ★★

Wrap str.isdigit in a Verity predicate all_digits(s) whose refutation names the first non-digit character, like string_ops.is_alnum does. (Hint: forall and enumerate.)

Exercise: the or idiom ★★★

Take a position on the first design note in Section 7.7. Write three short programs whose behavior differs between the two options and say which behavior you'd want.
